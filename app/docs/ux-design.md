# 界面设计语言与交互规范（ux-design）

面向后续开发的一致性守则。每条规范都对应一个已验证的验收门（verify/logs 下各门），
改界面时先读本文，改完必须让对应门继续 PASS；门即规范的可执行形式。

## 1. 用户画像与设计立场

目标用户是机械组成员与学生用户：会画三维图、上过力学课，但没有用过求解器命令行、
不知道什么是节点号/面号/INP 文件，机房机器配置参差。由此推出五条立场：

1. **流程可见**——不知道下一步是什么，就让界面把「缺什么」写在下一步按钮上
   （流程条 7 步：导入→材料→约束载荷→网格→求解→结果→报告；未完成步骤按钮文本
   直接带「缺少：固定面/载荷定义」这类字样，点击直达设置入口）。验收：
   `verify_workflow_navigation.py`（占位页 3 入口、7 步 hint、错误态文案）。
2. **面向对象操作**——不让学生数面号。约束/载荷/连接统一「在三维视口里点那个面」：
   悬停给部件名+面号+面积+法向，点击高亮并写卡片，误点可逐条撤销。验收：
   `verify_face_pick_card.py`、`verify_face_pick_to_form.py`。
3. **诚实呈现**——没有求解证据就一个数字都不显示（仪表卡片 badge「未计算/未验证」，
   无屈服强度安全系数显示「—」）；未绑定节点、需复核连接、历史结果都用醒目但
   不夸大的方式标注。**宁可少显示，不可虚报**——这是全产品的红线，UI 是第一道执行者。
   验收：`verify_busy_state_and_dashboard.py`（取消后卡片 payload 全 None 且无数值）。
4. **中文优先**——按钮、菜单、错误、提示全中文；不出现 OK/Cancel/Yes/No，
   不暴露几何内核内部名（装配树显示「部件1/部件2」，不是 OCC 的 Part 标签）。
   验收：`verify_theme_and_naming.py`（6 对话框按钮盘点、QDialogButtonBox 必经
   `chinese_button_box` 包装、装配树无『Open CASCADE』）。
5. **环境兜底**——机房机器可能没有 GL、没有字体、内存紧张。GL 不可用自动降级
   Agg 静态画布（此时点面不可用，界面要给出面列表等替代路径，并在日志写明降级）；
   内存不足时守卫截停而不是吃光内存把整机拖死，并把原因写进工况日志。

## 2. 视觉规范

- **主题**：现代浅色主题 + 品牌强调色（accent）。accent 用于主按钮、流程条完成态、
  选中高亮的边框色（`verify_theme_and_naming.py` 断言 accent 像素存在）。
- **状态徽章色**（仪表卡片可信度，与计算报告同口径，别处不得复用同色表达别的意思）：
  - 绿色 = 已验证（有求解证据且无警告）；
  - 橙色 = 待复核（如「连接待检查」）；
  - 红色 = 不可信（日志含 ERROR）；
  - 灰色 = 未计算/未验证（此时卡片不出现任何数值）。
- **状态文字色**：校验错误用红色、通过未计算用深绿 #1b5e20（工作台分组树行为，
  `verify_workbench_ux.py` 断言前景色）。
- **字体**：界面中文标题/色标标注用微软雅黑（C:/Windows/Fonts/msyh.ttc；
  `verify_viewport_state.py` 断言）。offscreen/无字体环境下 Qt 可能枚举不到中文字体
  （截图呈方块，ARCHITECTURE 模块40 记录的环境限制）——验收以程序化文本断言为准，
  不以 offscreen 截图中文可读性为准。
- **对话框**：一律经 `chinese_button_box` 生成按钮（确定/取消/关闭/是/否的中文等价），
  禁止直接例化 QDialogButtonBox 或写英文按钮字面量（源码扫描门）。

## 3. 交互规范

### 3.1 三维点面（核心交互）

- **链路固定**：悬停 tooltip（部件/面 tag/面积/法向，数据与 `face_by_tag` 同源）→
  左键点击选中并高亮 → 右侧属性面板与「选中面卡片」同步 → Ctrl+Z 或卡片按钮撤销。
- 撤销栈逐条回退（连续误点、点空白清除都可退回上一个选中面）；快捷键标注
  「依赖平台焦点，主路径为按钮/信号」。
- **A/B 面轮转与守卫**：点面直连表单中第一个点击写 A 面、第二个写 B 面，继续点击
  更新 B 面；下拉与视口双向高亮；选了连接类型没选 B 面给中文守卫提示（如
  「请点三维视口中的第二面」），不静默默认。已知缺口（如实记录）：添加一条定义后
  点面仍写 B 面，单面类型（固定/面力）连加第二条需重开表单或用下拉——后续若实现
  「添加后回到 A 面」，必须同步更新 `verify_face_pick_to_form.py` 的轮转断言。
- **结果视图同样可点**：结果三角形附着 occ tag，点击显示归属部件+挂接定义+局部极值；
  无挂接面明确标注「无挂接定义」且不产生归属高亮。归档缺归属数据时溯源不可用并提示。
- Agg 降级时点面不可用——所有点面入口必须在同一对话框内保留部件面列表等价路径。

### 3.2 忙碌态（busy）动作门控

- 求解/网格运行中：**修改类动作禁用**（新建/打开/保存工程、导入、材料、工况、网格编辑、
  高级），**查看类保持可用**（云图、历史、报告、视口、帮助）。当前实测口径：
  修改类 20 个 QAction 全禁用、查看类 11 个全开放，进入时快照、结束/取消后恢复
  （`verify_busy_state_and_dashboard.py`）。
- 新增 QAction 时必须归类（修改/查看）并接入快照恢复机制；漏注册的动作在 busy 态
  就是并发隐患。
- 「取消计算」必须：停止后台阶段与子进程树、输入与日志保留、结束后移除取消按钮并
  恢复动作、仪表回到「未计算/未验证」且无数值。

### 3.3 反馈与文案

- 每步缺什么直接写出来（「缺少：…」「未指定材料：零件」），错误文案格式 =
  「哪一步 + 缺什么/错什么 + 怎么办」（如「请先把网格尺寸放大到约 X mm 再试」）。
- 求解按钮的三态文案是诚实规范的样板：未注册→「当前高级后端尚未接通；这里不会启动
  求解」；后端接通但编排未接线→「求解（后端已接通；工作台求解编排尚未接通，这里不会
  启动求解）」并禁用。**按钮禁用时必须告诉用户为什么**。
- 历史结果展示必须带「历史」标注与口径说明，不与当前工况混写。
- 数值展示分层：正文 4~6 位有效数字，全精度进报告附录与 results.json（门内断言
  正文与全精度差 ≤ 打印精度的一半）。

## 4. 与学生用户的对应关系（为什么这样设计）

| 学生遇到的困境 | 设计对应 | 验收门 |
|---|---|---|
| 不知道该点哪一步 | 流程条把缺什么写在按钮上 | workflow_navigation |
| 不会数 CAD 面号 | 三维视口直接点面 + 悬停提示 | face_pick_card / face_pick_to_form |
| 看不懂英文界面 | 全中文按钮/菜单/错误，无内核内部名 | theme_and_naming |
| 分不清「算过了」和「能信吗」 | 仪表徽章四色 + 未计算不显示数 | busy_state_and_dashboard |
| 怕点错、不敢点 | 悬停预览 + 撤销栈 + 守卫提示 | face_pick_card |
| 机器卡死/内存爆 | busy 门控 + 内存守卫截停 + 日志留证 | busy_state / memory_budget_guard |
| 机房没有 GL/字体 | Agg 降级 + 面列表替代路径 + 日志写明 | main_entry / viewport 系列 |

## 5. 新界面开发检查单

新增对话框/面板/动作时逐条过：

1. 按钮全中文？经 `chinese_button_box`？无英文按钮字面量？（theme_and_naming 会扫）
2. 显示部件/面的地方用的是用户可读名（部件1/面 2），不是内核内部名？
3. 数值展示：没有证据时是否有「未计算/未验证」路径？徽章/文案与报告同口径？
4. 新 QAction 是否已归类修改/查看并注册 busy 快照恢复？
5. 需要点面的入口是否保留 Agg 降级下的面列表等价路径？
6. 错误/守卫文案是否「哪一步+缺什么+怎么办」三段齐全、中文？
7. 长任务是否有取消入口、取消后输入与日志保留？
8. 对应验收门是否更新并复跑 PASS？（门即规范的可执行形式——改了交互不改门，
   等于改了契约没告诉任何人）
