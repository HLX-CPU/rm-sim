# 模块29：静力后台流程

静力计算改为顺序执行的独立准备进程、CCX进程树、独立整理进程。主窗口轮询真实阶段和耗时，不显示虚构进度百分比。其他分析、导入、工程打开/保存等操作的后台化不包含在本模块中。

## 过程和记录

- `solver/workflow.py`调度流程，`workflow_job.py`执行准备和整理；同一任务的重阶段不并行驻留。
- `prepared_store.py`保存数值网格和配置，`display_store.py`保存已经从原始结果构建的数值显示包。NPZ读取禁用pickle，并核对SHA256、有限值和摘要。
- `tasks.py`新增文件提交和`solved_unparsed`终态，供后台流程把“求解已结束”与“结果已解析”分开。现有默认同步入口仍保持结束标记和解析均成功才算completed。
- GUI不重新解析整份INP/FRD；部件表面在整理进程中构建。窗口接收当前数值数组后，任务历史释放其重复引用。
- 固定/加载面通过指纹传递；跨进程不能只传旧面号。材料数值先冻结为快照。
- 每次准备复制源STEP并核对前后哈希；每个求解工况内再保留独立`geometry.step`。源CAD不写入。
- `tasks/task_*/`保存请求、阶段事件、标准输出/错误、准备包和任务终态；进入求解的工况还保留流程和阶段记录，随工程束cases目录保存。

## 取消与内存

准备、求解、整理均由本次专属Windows作业管理；取消或关闭窗口停止本次进程树。取消准备不启动CCX；取消整理不把新工况加入当前工程索引，原始求解记录保留。导出网格只在完成后替换所选文件，取消不覆盖旧导出。

独立重阶段预算取当前可用内存55%且最多8 GiB；CCX沿用模块28的作业预算。最终数值包载入另设保护预算（文件体积4倍加128 MiB）；这些是保护上界，不是精确内存预测。

网格预览不要求材料、固定或载荷，也不自动确认材料；结构求解仍检查材料、工况、约束、连接和网格质量。

## 验证边界

- `verify_background_workflow.py`：真实准备/CCX/整理，Qt心跳、两类取消、关闭窗口取消、旧工况哈希、导出保护、缺失材料、独立网格预览、显示包损坏拒绝和历史原始结果互核。
- `verify_real_assembly_prepare_cancel.py`：本机20实体分析副本，39条连接和NEW壳体固定侧通过指纹传入后台；只验证准备取消，不提交整装CCX，非强度验收。
- `verify_workflow_bundle_relocation.py <后台验证记录.json>`：新流程的真实工程束换目录解包，阻止读取旧工作目录，恢复归档原始场并核对全部case哈希。
- 心跳从模型已显示到视口开始测量；首次GL初始化单独验收。离屏下使用Agg后备，不能据此宣布原生GL交互通过。
