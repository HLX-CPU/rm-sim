# 模块28：求解日志、进程树与连接诊断

本模块补齐真实任务的日志、停止和警告反馈，不代表整套软件实际使用验收通过。

后续模块29已将静力准备和整理也接入后台可取消流程；本模块的进程管理与日志机制继续复用。

## 日志和状态

- 调度器持续写本次工况的 `<job>.log`（UTF-8）及 `<job>.stdout.log`、`<job>.stderr.log`（原始字节）。
- `SolveTask.log_text` 只保留末尾1 MiB；`Job finished` 判据扫描完整落盘日志，不以末尾摘要代替完整日志。
- `<job>.task.json` 记录 pending/running/completed/failed/cancelled、真实退出码、解析状态、错误及资源数据。运行中约每0.5秒更新，终态另行记录。
- 保持“正常结束标记 + 结果可解析”的判据；只有结束文字而无DAT/FRD，仍然失败。

## Windows进程树

`solver/process_group.py` 用Windows Job Object管理本次进程树。先以CREATE_SUSPENDED创建启动器，加入作业后再恢复初始线程，子进程继承作业归属；避免启动器已经创建子进程后才纳入管理的空窗。

取消时终止整个作业；作业句柄关闭也会终止残留子进程。没有按进程名批量结束程序，因此不会结束其他人的同名进程。GUI状态栏提供“取消计算”，取消完成后恢复菜单；计算中关闭窗口会先取消本次作业，再关闭窗口。

自动预算使用启动时可用物理内存的60%，再除以该调度器最大并发数。Windows作业内核限制设为预算的90%，给本机分配和记账保留余量；当前可用物理内存不足2 GiB时也停止本次作业。预算是保护措施，**不是求解内存预测模型**。

后续运行时以实际内核限制的98%触发主动停止，避免原生分配器触顶后停滞。
串行任务配置最大并发1。异常退出时仅观察到峰值接近限额，不足以确认崩溃原因；
状态文件分别记录主动停止和接近限制后自行退出。见[模块33](module_33_runtime_regression.md)。

`resource_usage`记录的是进程树峰值提交内存，不是工作集。本机观测到峰值记账略高于配置限制，具体原因尚未确定；原始预算、内核限制和峰值分别保留，不把峰值裁剪到限制内。未对整装建立可靠预测标定前，不从小算例外推整装预算。

非Windows路径使用独立进程组；Windows作业的提交内存计量在其他平台明确不可用。

## 连接警告

`solver/diagnostics.py`读取本次CCX的未绑定节点集合，记录不同编号数量、原文件名及SHA256；可按连接从面匹配包含中间节点的C3D10六节点面。

存在警告或警告文件无法读取时，报告与结果标签要求检查连接。允许查看场结果供排查，但不能把“计算结束”说成连接或结构合格。警告编号可能参与多个绑定，不可直接解释为最终整体悬浮节点数量。没有警告文件也不等于结构验收通过。

历史结果重开时在内存中重新检查旧警告文件，不改写旧报告、原始结果或旧归档哈希。

## 验证边界

- `verify_scheduler_lifecycle.py`：真实Windows进程测试，包含36 MiB输出、仍在运行时日志已落盘、有限日志摘要、子进程取消、无关同名进程存活、启动器退出后残留清理及受限分配。C#测试程序不是有限元求解器，不用于证明物理计算。
- `verify_tie_diagnostics.py`：真实CCX局部重叠绑定，小算例正常结束、反力平衡，但报告仍显示53个警告节点；重开历史不改原始产物。另核对DS旧工况的6759个编号。
- `verify_solver_gui_lifecycle.py`：离屏窗口的取消按钮、关闭窗口取消和菜单恢复；不等于真实桌面人工交互验收。
- 默认全回归清单加入上述三项；完整结果见本轮报告。
